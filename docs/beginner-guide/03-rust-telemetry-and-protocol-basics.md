# 03. Rust、遥测与协议基础

## 3.1 Workspace 依赖方向

`xsos-protocol` 位于依赖图底部，Client 与 Server 都依赖它。协议 crate 不应反向依赖任一运行时，也不
应读取环境、数据库或文件。这样相同 DTO、枚举和边界由编译器在两端共同验证。

## 3.2 一份报告不是任意 JSON

报告包含协议/应用版本、稳定 Host 身份、唯一 report ID、采样时间和受限指标。每个数值必须有明确单位、
合法区间和缺失语义。平台没有某传感器时应表达 absence，不能用零伪装“已采集且为零”。

## 3.3 跨语言整数

JavaScript 对大于 `2^53-1` 的整数不能精确表示。Client wire protocol 的大计数使用明确的安全编码与解析
辅助模块；移动宿主不能先把它读成不精确 Number 再转换。当前 Web 只消费 Server 汇总后的有限数值，
没有读取完整 Client report；若未来把计数器加入管理 API，才必须同步设计浏览器表示与 guard。

## 3.4 采集器设计

采集器只读取平台事实，返回模型或分类错误；调度、重试和网络不进入采集器。快速指标与慢速指标采用
不同周期，避免每十秒枚举昂贵设备。所有集合要有数量和字符串长度上限，以防异常驱动或系统接口产生
无界报告。

## 3.5 Rust 所有权在这里的意义

- report 在进入 spool 后拥有稳定 ID，重试不能创建新逻辑报告。
- delivery task 取得批次所有权后负责确认或归还。
- credential 更新先写临时文件、同步并原子替换，内存状态只观察完成的文件。
- Server writer 接管已入队请求后，即使客户端断开也必须完成并回应内部结果。

这些不是语法偏好，而是故障时“谁负责收尾”的证明。

## 3.6 时间语义

采样时间来自系统时钟，但调度间隔与超时应依赖单调时钟。Server 必须限制过远的未来时间、无效时间和
不合约格式。小时聚合使用 UTC 桶，UI 再按用户时区展示，不能在持久层混入本地夏令时歧义。

## 3.7 错误分类

至少区分：配置错误、权限/平台不支持、暂时采集失败、网络可重试、认证永久失败、协议拒绝、Server
过载和本地状态损坏。把全部错误都变成重试会形成请求风暴；把全部错误都丢弃会静默丢遥测。

## 3.8 修改协议的联动清单

1. 修改 `xsos-protocol` 的 DTO、校验与测试。
2. 更新 Client 构造逻辑和所有平台 fixture。
3. 更新 Server 验证、持久化、聚合与 API 输出。
4. 若该字段进入管理 API，再更新 Web 类型、exact guard 与展示；否则记录 Web 不消费它。
5. 更新当前协议身份、文档和发布合同。
6. 删除被替代字段，不留 alias 或双写。

## 3.9 动手练习

选择一个只读标量，从平台采集器跟到 `ClientReport`、JSON fixture、Server 入队、SQLite 标量列和 Host
列表 API。再检查当前 Web 是否消费该 summary 字段。记录每层的单位、nullable 语义和最大值；若无法
确定，说明字段文档或测试仍需加强。
