# 新建实例与配对

在管理台创建实例，再在主机运行 xsoc 设置向导即可完成配对。

1. 点击「新建实例」后立即以默认名称创建；名称可在详情中修改，允许 1–32 个 Unicode 字符。首尾按 Unicode White_Space 裁剪，控制字符会被拒绝。
2. 实例密码（协议字段 `authorization_code`）不设有效期，由服务端加密保存，可在详情中查看或在列表中更换；不要放入 URL 或日志。
3. 按 [xsoc 安装指南](https://github.com/isarmg/xsoc/blob/main/docs/platform-setup.md)安装客户端，在管理员终端停止服务后执行 `xsoc setup --interactive`（Linux/macOS 加 sudo）。向导询问服务端 HTTPS 根地址和实例密码，并直接提交激活。授权码会明文回显，请在受保护终端输入。
4. 向导设置自启、启动服务并验证连接。回到管理台确认收到新报告；密码不会因本次配对而被消耗。
5. 更换密码后旧客户端凭据失效。在同一主机停服并用新码执行 `xsoc pair recover --interactive`，核对结果后启动服务，可保留原 Host UUID 和历史。未使用的实例也可取消。

密码没有到期字段或定时失效逻辑。设备发起的短期配对请求仍有 15 分钟会话期限以限制未认证请求占用；请求超时不取消密码，Client 可重新发起请求。此期限不是密码有效期。

取消与绑定在数据库事务中互斥，已绑定实例通过更换密码撤销旧凭据并重新配对。管理员认证、CSRF、设备确认和审计继续保留。
首次激活或重新激活后，实例在收到第一份新报告前显示离线，且重新激活不会展示旧客户端的最新详情。客户端采集时间最多允许领先服务器五分钟；超过此范围的报告返回可重试的 `report_future_timestamp`，等待时钟接近后仍可提交原始报告。最新详情按采集时间与接收时间中的较早者排序，以免时钟校正后被先前的未来样本占住。

## Web 上报日志

实例的「日志」页默认选择服务器当天，可直接编辑起止年月日并按回车查看包含起止当天的日期范围。
服务端按每份报告的接收时间归属服务器日期，每页最多 50 条，以游标提供首页、上一页和下一页；
切换日期范围或刷新会重新读取首页。每条记录显示服务器时区下的接收时间、客户端采集时间和报告 ID，
客户端补传或时钟偏差不会改变所属日期。页面只保留当前页，仍在保留期内的历史可以逐页访问。
Web 响应最多 8 MiB、HTTP 等待最多 5 秒，SQLite 查询预算最多 3 秒；读取繁忙时返回可重试 429。
已按保留策略清除的报告不再出现在该页。

当前数据库格式为 xsos `1.0.0` / Schema `1`，应用发行版本为 `1.0.0`。
启动严格校验当前数据库身份；只接受完整当前状态，详见[数据库身份](reference.md#数据库与保留)。
